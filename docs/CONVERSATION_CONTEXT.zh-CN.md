架构文件：

## 2. 用户已确认的产品需求

### 登录与页面

最初需求是本地数据库预创建50个账户，以登录ID和密码登录，**不提供普通用户自助注册**。数据库存密码哈希，初始密码另在本机私有文件中保存。

打开网址后，未登录用户进入登录页；登录后进入带“今日食谱图片”的首页。主要入口包括：

- 用户信息设置。
- 聊天推荐饮食。
- 推荐历史和换餐。

界面支持中文、英文、日文。资料不足时，图片卡片应明确标为未个性化食谱示例，不能宣称已经适合该用户。

### 收入与预算

用户档案增加年收入档次。用户确认口径为：**个人税前年收入，币种日元JPY**。

最初的演示配置：

| 档次 | 年收入区间 | 默认每日预算 |
|---|---|---:|
| JPY_A1 | 0至不足200万日元 | 900日元 |
| JPY_A2 | 200万至不足400万日元 | 1100日元 |
| JPY_A3 | 400万至不足600万日元 | 1300日元 |
| JPY_A4 | 600万至不足800万日元 | 1500日元 |
| JPY_A5 | 800万至不足1000万日元 | 1700日元 |
| JPY_A6 | 1000万日元及以上 | 1900日元 |

这些区间和预算是项目演示配置，不是官方收入分类或实际消费统计。

采用预算的优先级为：**本次明确预算＞档案自定义预算＞收入档次默认预算**。收入影响预算与可选食材，不能降低健康或过敏限制。

### 聊天边界

用户明确要求：输入与饮食无关的内容时，回复正文必须逐字为：

> 无法回答与饮食无关的内容

该句在中英日界面下都保持中文，不附额外解释、标点、引用或菜单。后端执行分支并输出固定常量，不能只依靠模型提示词。

饮食、食材、营养、做法、饮食费用和为饮食推荐补充的资料属于有效输入。“太贵了”“换一个”“不要鱼”等需要结合当前用户的会话。饮食任务与独立无关任务混合时，原计划采用整条拒答策略。

## 7. 服务停止与启动对话

用户多次要求停止项目全部服务。应区分以下四项：

1. 网页／后端API。
2. 推荐worker。
3. 项目PostgreSQL Docker数据库。
4. Ollama Docker模型服务。

`scripts.service stop`只管理API和worker，**不会停止数据库或Ollama**。关闭浏览器或终端也不等于停止这些后台服务。

当前账户曾无法访问Docker socket，且`sudo -n`报需要密码。因此API和worker能够直接停止，数据库与Ollama需要用户在本机终端输入管理员密码。

对话中曾检查到所有相关端口无监听，确认当时全部停止；之后又检查到5433和11434重新监听。**停止状态会变化，不能把一次检查当作永久状态。本文整理过程未启动、停止或检查当前服务，当前状态须重新查询。**

### API与worker管理

在项目根目录运行：

```bash
cd /home/aitd/hypertension-diet
backend/.venv/bin/python -m scripts.service start
backend/.venv/bin/python -m scripts.service status
backend/.venv/bin/python -m scripts.service restart
backend/.venv/bin/python -m scripts.service stop
```

`api: stopped`和`worker: stopped`仅说明这两个进程已停止。status打印的网址是访问提示，本身不是服务存活证明。

### Docker数据库与Ollama

```bash
cd /home/aitd/hypertension-diet
sudo docker compose stop db
sudo docker ps -a --format 'table {{.Names}}\t{{.Status}}\t{{.Image}}'
```

用列表中确认的Ollama实际容器名执行`sudo docker stop 实际容器名`或`sudo docker start 实际容器名`。对话中曾确认Ollama容器ID前缀为`9fb9385ca06a`，但容器重建后ID可能变化，不应无条件沿用。

数据库启动命令：

```bash
sudo docker compose up -d db
```

Ollama启动后等待就绪并验证：

```bash
curl --fail --silent --show-error --max-time 10 \
  http://127.0.0.1:11434/api/version
```

### 2026-10-12的启动命令误解

用户执行：

```bash
read -r -p "ollama" DIET_OLLAMA_CONTAINER
```

`"ollama"`只是显示的输入提示，不会给变量赋值。如果直接回车，变量为空，后面的`if [ -n "$DIET_OLLAMA_CONTAINER" ]`会跳过容器启动。这可以解释输出中没有启动结果、curl连接11434失败的情况；具体容器是否另有故障仍需检查。

如果继续使用交互输入，应写为：

```bash
read -r -p "请输入实际 Ollama 容器名：" DIET_OLLAMA_CONTAINER
if [ -n "$DIET_OLLAMA_CONTAINER" ]; then
  sudo docker start "$DIET_OLLAMA_CONTAINER"
fi
```

提示出现后需实际输入容器名。curl的`--max-time 10`只限制请求耗时，不会自动等到服务启动或反复重试。
