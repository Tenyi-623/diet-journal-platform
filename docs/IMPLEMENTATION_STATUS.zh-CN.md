## 当前启用的演示规则

- 支持已确认资料的合成成年人。未成年人、妊娠、糖尿病、肾病、其他未覆盖病况或不明过敏条件返回unsupported；已知不支持条件即使资料不完整也不展示隐含适用的首页食谱。
- 年龄、过敏状态、健康确认和演示目标确认缺失时追问；不把unknown当none。
- 能量默认2000kcal、钠默认2000mg只是用户可确认/修改的软件测试参数。能量允许±10%；收入不改变目标。没有声称这些数值来自已经审核的个人医嘱。
- 成本预算优先级：当次输入＞档案覆盖＞收入默认。49种配料价格和6档预算均为模拟数据。
- 明确的每日预算区间同时约束总花费下限和上限；单个预算值仍只作为上限。筛选器、独立校验、聊天、换餐、历史与三语预算展示均保存/使用下限，区间无解时给出原因，不返回低于下限的组合。
- 金额已增加中文数字解析，明确的本次预算优先于模型输出和旧对话金额。指定食材类别及餐次要求进入筛选与独立校验；已补充无盐烘烤巴旦木、烘烤核桃和6道三语坚果早餐；原始营养数据、过敏筛选与图片管理一并接入。相关请求会校验早餐含坚果、全天含鱼及预算上下限；其他菜谱缺口仍明确说明。补充验收见 `evaluation/nut-catalog.json`。
- 食谱只使用模板与离散份量；直接从结构化食品表计算数字，模型不能改写结果。
- 钠Tr使用成分表显示精度上界；这只约束表值估算，不能保证实际食物测量值不超出。
- 健康条件或已知过敏档案不再一律阻止知识问答：问答会带入最少必要的健康/过敏上下文检索资料，并解释个人判断的限制。提问明确涉及档案中的过敏原时，先返回确定性的过敏限制说明和 NHS 公开参考资料，不允许模型覆盖该限制。外部安全参考资料单独标注，不冒充上传知识库的检索结果。一般知识回答仍依赖候选资料，未完成人工支持性审查；特殊人群定量菜单的限制仍保留。
