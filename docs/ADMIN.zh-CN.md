# 管理后台

入口：本机网页登录后，左侧显示账号有权访问的“管理菜单”。

初始管理员登录ID为 `admin`，随机密码保存在本机
`data/private/admin-account.csv`（文件权限0600，已忽略Git）。
网页新增的用户会生成随机密码，创建或重置成功时仅显示一次。
管理员日常改密仍使用“用户信息”里的修改密码功能。

## 角色与权限

| 角色 | 权限 |
|---|---|
| 普通用户 `user` | 原有资料、聊天、推荐与历史功能 |
| 管理员 `admin` | 用户、角色分配、菜谱和知识库管理 |
| 用户管理员 `user_manager` | 新增、启停、重置普通用户；不能管理管理员或分配管理角色 |
| 菜谱管理员 `recipe_editor` | 新增、编辑、启停菜谱，上传图片 |
| 知识库管理员 `knowledge_editor` | 上传PDF、查看提取原文、编辑元信息与启停检索 |

数据模型为 `app_users → app_user_roles → app_roles → app_role_permissions → app_permissions`。
角色可以组合；没有管理权限的用户看不到管理菜单，直接调用管理API也返回403。
`/api/auth/login` 与 `/api/me` 返回当前角色和权限；后端每次请求重新查询权限，
不信任浏览器传来的角色或菜单状态。

用户列表支持搜索和分页。角色或启停状态变更、密码重置后撤销目标用户全部会话。
不允许禁用自己或修改自己的角色，不能移除最后一个启用的管理员。
账号停用保留历史记录，没有删除用户历史的管理入口。
保留原有Cookie、CSRF、Origin检查；所有管理变更写入 `app_admin_audit`，
审计记录不含密码，运行账号无权更新或删除审计记录。

## 菜谱与图片

当前初始目录共184道：早餐54道、午餐65道、晚餐65道，使用49种已接入的食材。
菜单管理支持按三语名称、编号或已维护的关键词搜索、按餐次筛选，每页显示24道。
新增158道是应用编写的配方，包含基准份量、三语做法、计算来源和可替换的食材示意图；
食品成分表提供营养数据，不代表该来源发布或审核过这些配方。

支持三语名称、餐次、做法、准备时间、配料和可食重量。只能使用已有结构化营养数据的配料，
保存时复用营养计算器检查；保存和图片替换会刷新首页缓存。
菜谱保存使用版本校验，其他管理员已修改时返回409，请刷新再编辑。
新建菜谱先保存，再上传图片。

图片支持PNG、JPEG、WebP，最大4MB、2000万像素；服务端验证并重新编码成最长边1600像素的WebP，
不接受SVG/HTML。图片存放在 `data/uploads/recipes/`，
使用内容哈希命名，通过登录保护的 `/api/recipe-media/{hash}.webp` 读取。
替换图片生成新URL，历史快照保留旧图；停用菜谱不会删除历史记录。
不要手工删除旧图片，否则历史快照中的图片会失效。

初始SVG在 `frontend/public/recipe-art/`，通过 `/api/recipe-images/{id}` 显示。
新目录的图片编号形如 `r178-l001`、`nuts-b001`，仍可从后台上传照片替换。
原有20道菜谱、管理员修改及上传图片不会被目录导入覆盖。

已补充无盐烘烤巴旦木（食品编号 `05040`）和烘烤核桃（`05014`），以及6道坚果早餐（`nuts-b001` 至 `nuts-b006`）。搜索“坚果”、`nuts` 或 `ナッツ` 可查看全部6道。新食材的营养值来自已有食品成分表，保留原始微量标记及来源，价格是估算值；坚果过敏档案会排除这些菜谱。

### 目录维护

新增配方定义：`backend/app/recipe_catalog.py`；坚果补充为 `backend/app/nut_catalog.py`。一次性补充现有数据库：

```bash
backend/.venv/bin/python -m scripts.make_catalog_art
backend/.venv/bin/python -m backend.app.recipe_catalog_install
backend/.venv/bin/python -m scripts.make_nut_art
backend/.venv/bin/python -m backend.app.nut_catalog_install
backend/.venv/bin/python -m scripts.service restart
```

导入使用数据库所有者连接，在单事务中校验食材编号、全部份量档的能量/钠计算和图片存在性；
重复运行不会覆盖已有同编号记录，新安装的 `backend.app.seed` 也会包含这些菜谱。
实际数据库若另有管理员新增菜谱，总数会高于184；导入不会为凑数量删除数据。
重生成插画后须重新构建前端，以同步 `frontend/dist/` 的静态文件副本。

新增食材沿用已有食品成分表的编号及生熟状态，不重新录入或编造营养值。
干意面按干重计量，保留煮面液的做法与配料累计计算口径相配；
不使用成分表中“1.5%盐水煮熟意面”的营养值替代无盐配方。
面包的麦、奶、蛋、豆标记采取保守处理，实际商品须核对包装。
价格仍为估算值，准备时间为配方估计，配方尚未经临床或营养师审核。

推荐筛选按食品类别排除鱼肉，保留原有蛋奶素定义；新加入的鸡里脊、猪里脊、鲭鱼和鳕鱼均受约束。
组合搜索仍比较全部可行组合，通过能量区间和预计算减少开销，不先截断候选菜谱。
验收记录见 `docs/evaluation/catalog-178.json`。

## 知识库

支持PDF上传（最大12MB、200页、500片段）、标题/机构/版本/资料类型/适用说明编辑，
逐页查看提取原文，以及控制文档是否参与检索。
上传队列持久化在 `app_kb_uploads`，由现有worker处理。
当前正在执行的导入会占用模型队列，后续聊天会排队；建议较大的资料在低峰期导入。
失败任务显示错误并可重试；进程中断后租约过期可以恢复。

目前提取PDF文字层，不自动对上传扫描件进行OCR。文字不足、乱码和疑似成分表格页会隔离；
历史指南默认隔离。现有离线OCR修复流程仍可使用。
导入完成的文档默认停用，管理员核对原文后手动启用；隔离或未完成的文档不能启用。
停用在检索排名之前生效，旧推荐已经保存的引用快照不改写。
启用仅控制可检索性，不代表临床审核通过。

原PDF保存在 `data/uploads/knowledge/`，这些路径不能通过网页任意指定。
重复文件会被拒绝；失败任务应使用“重试”，无需重复上传。
修改元信息不改变原文和向量；更新原文请上传修订PDF，并停用旧版本。

## 迁移与维护

新增迁移为 `002_rbac_admin.sql`。原有50个用户保留普通权限，
用户ID改为序列，可继续新增账号，不再受50个账号上限约束。

```bash
backend/.venv/bin/python -m pip install -r backend/requirements.lock.txt
backend/.venv/bin/python -m backend.app.setup
backend/.venv/bin/python -m scripts.bootstrap_admin
backend/.venv/bin/python -m scripts.service restart
```

`bootstrap_admin` 只创建不存在的 `admin`，不会重置已有账号密码或更改已有角色。
上线迁移前已生成数据库备份；之后备份数据库时还须同时备份 `data/uploads/`、
私有配置和管理员凭据。数据库dump不包含上传文件。

验证：`backend/.venv/bin/python -m scripts.test_application`。
该命令只使用隔离库 `diet_restore_check`。

## 界面语言

右上角语言选择同时控制用户管理、菜单管理和知识库管理的中、英、日文界面，
包括按钮、筛选项、角色名称、状态、分页、字段标签和已知操作提示。
菜谱与食材名称读取所选语言；缺少该语言内容时回退到已有名称。
编辑框保留三种语言各自的名称和做法，切换界面语言不会自动翻译或覆盖数据。
知识库原文、文档标题、机构名及管理员填写的说明保留原文，避免改写来源信息。

新增158道菜谱的SVG示意图有三语标签，由
`/api/recipe-images/{id}?lang=zh|en|ja` 返回对应图片；早期无文字插画可共用原图。
上传照片继续使用原有 `/api/recipe-media/` 地址，不修改文件或映射。
管理翻译词条位于 `frontend/src/adminI18n.ts`，新增界面文案需同步提供三语。
